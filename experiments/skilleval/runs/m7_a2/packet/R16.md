## Prompt audit — prompt.md

**Summary:** This prompt defines a fairly tight contract for turning invoices into a JSON record (routing fields, extraction rules, a full schema), but it has one real conflict (single-line vs. pretty-printed output), two facts the model can't guess (rounding rule, review threshold), and three odd work orders that ask the AP review field to carry a greeting, a productivity tip, and a procurement tip — which fights the field's own stated purpose.

| Work orders | 4 | 12.5% |
| Restrictions | 4 | 12.5% |
| **Total** | 32 | |

- **Size:** ~460 words (~600 tokens)
- **Contract share:** 75% — lean. Most of the length is the field schema, which is cheap reference text, not the problem.
- **Issues:** 7 — 3 high · 2 medium · 2 low

### Findings

1. **Restated capability** · low · L3
   > "You are a helpful, knowledgeable assistant."

   Tells the model nothing about this task — it's already helpful by default.
   **Proposed:** delete

2. **Duplicate** · medium · L11 and the Delivery checks table row "Invoice identifier"
   > "Copy the supplier invoice number exactly as printed."

   Stated once in Intake and routing, again in the Delivery checks table.
   **Proposed:** delete the Delivery checks table row; keep L11.

3. **Emphasis for precision** · low · L12
   > "KEEP SUPPLIER CAPITALIZATION"

   All-caps doesn't make the rule more likely to be followed; it reads as an afterthought.
   **Proposed:** replace with "Preserve the supplier name's capitalization exactly as printed." as a plain bullet near L11.

4. **Vague contract** · high · L13
   > "Round monetary amounts appropriately."

   "Appropriately" isn't a rule — round half-up? to 2 decimals? to the currency's minor unit? The model has to guess.
   **Proposed:** see Needs your decision #1

5. **Missing contract** · high · L14
   > "Set review_required to true when the invoice total exceeds the configured review threshold; otherwise set it to false."

   "The configured review threshold" is never stated anywhere in the prompt. Without a number, review_required is a guess on every borderline invoice.
   **Proposed:** see Needs your decision #2

6. **Conflict** · high · L23 vs. L47
   > L23: "Return the entire JSON record on a single line."
   > L47: "Pretty-print the JSON record with each top-level field on its own line."

   These can't both hold in one response. Nothing says which wins, so output formatting is unpredictable from run to run.
   **Proposed:** see Needs your decision #3

7. **Work order to confirm** · medium · L24, L25, L26
   > L24: "Include a friendly greeting in extraction_notes."
   > L25: "Suggest a general productivity habit in extraction_notes."
   > L26: "Offer a procurement tip in extraction_notes."

   These ask for conversational filler inside the one field the Record contract (L43) defines as "observations for the intake reviewer." If followed, a reviewer scanning extraction_notes gets a greeting and a productivity tip instead of useful observations, on every invoice. Unverified whether the model currently complies — but the three lines cost output tokens on every run and work against the field's own definition.
   **Proposed:** see Needs your decision #4

### Keep as-is
- L6 — contract: processing objective, scope (one invoice per request, continuation pages, line item order)
- L9 — contract: names the OCR tool explicitly, defines when its output enters context
- L10 — contract: fixed `pipeline_id` / `schema_version` values
- L15, L16 — restrictions: no web search, no computing missing tax
- L18, L19, L21 — contract: extraction procedure, currency rule, null/date/number/language rules
- L28–44 — contract: full field schema (reference text; cheap, not a length problem)
- Delivery checks "Parseability" row — contract: output must parse as JSON
